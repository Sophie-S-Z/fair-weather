# ADR 0014: Launch rules for the sandbox, sharing, analytics, and the launch checks

**Status:** Accepted. The challenge task (M4.5) adds its calibration to item 6.

## Context

Milestone M4 builds the sandbox, seed links, the postcard GIF, the page exports, opt-in analytics, the still version for a browser without WebGL, asset retry, offline play, the "Where this model is wrong" page, type, the phone layout, and the launch checks T7 to T11 (spec 12.3, 12.4, 12.7, 12.8, 13, 15.2 to 15.4, 16, 17, 18, 19.1). The spec names these features but leaves gaps: whether a sandbox knob acts at once or on a new run, what each knob changes in the sim, what the four advanced switches do in a sim whose friendships are already one-sided (ADR 0002 item 2), what each challenge checks, how a link holds "Kith as the player left it" when the deterministic sim cannot rebuild a whole year, where analytics counts go when the game has no server (spec 3.4, 21.3), what an asset is in a build that bundles its data, and what "reach their end screen" means for runs that must not depend on CI speed. ADR 0008 item 6 pinned fflate for seed links; item 19 here replaces it.

## Decision

1. **The sandbox opens after Part 1 (spec 12.1, 13.1).** The title's Sandbox button is enabled once the *Book of Skies* has a page; before that it is disabled and says "The sandbox opens when you finish Part 1." Without WebGL it is disabled and says "The sandbox needs WebGL. This browser does not have it." The start choice offers "Your Kith" (when the profile keeps one), "A new valley", each finished valley by its title, "Go on with your last valley" (when a sandbox save exists), and "Open a valley file".
   - **Your Kith** is the base scenario `m0` with the Kith carry the profile keeps. The game keeps that carry when the fire keeps the year's page (the end of Part 1) and again when the homecoming ends, from the last snapshot. It holds only the creatures of `m0` and the ties between them (so never the hero), every number rounded to thousandths, and no diaries.
   - **A new valley** is `m0` with no carry and a new seed.
   - **A finished valley** (a valley the player played, not skipped, on this device; the profile lists them) is that valley's base scenario with its rule pack and no hero. Halcyon's `kithWarmth` is 0, so its Wisp stays.
   - Kith starts in spring; a valley starts in its scenario's season. A day lasts `story.dayLengthSeconds` (40 s). The population cap is `cap.sandbox` (60). The sandbox has no beats, bets, twists, or ambient sky bids. A run starts at 1×.
2. **A knob sets a run's start; a change starts the run again (spec 13.1).** Every knob is a tuning or scenario value that the worker reads at `init`, so a seed link needs only the setup and the commands. When the player changes a knob or a switch, the run starts again from day 0 with the same seed: the structures the player placed so far become the setup's `structures`, and the commands are dropped. The Rules panel says "When you change a rule, the valley starts again from its first day." A knob holds an integer index on a grid in hundredths, and its value is `(low + index × step) / 100`, so every value is the same double as its decimal (0.3, not 0.30000000000000004) in every engine. An unset knob leaves the tuning and the scenario as they are.

   | Knob (label) | Panel | Valley | What it sets | low, step, steps (hundredths) | Unset |
   | --- | --- | --- | --- | --- | --- |
   | Gift value | Rules | all | `gift.value`, and `gift.valueWinter` = max(0, value − 1) | 0, 50, 12 (0 to 6) | 3 |
   | Fog level | Weather | all | scenario `baseFog`: every fog cell starts at it | 0, 10, 10 (0 to 1) | 0 |
   | Bench density | Population | all | a bench at each of the scene's first n bench spots, id `sandbox-bench-<spot id>` | 0, 100, the scene's spot count | 0 |
   | Gossip threshold | Network | all | every creature's Ear; only while Mixed thresholds is off | 0, 5, 20 (0 to 1) | 0.5 |
   | Imitation rate | Rules | all | `imitation.rate` | 0, 5, 20 | 0.3 |
   | Wind strength | Weather | all | `wind.dialShiftChance` | 0, 5, 20 | 0.2 |
   | Season length | Rules | all | scenario `seasonDays` (item 4) | 200, 100, 12 (2 to 14 days) | 7 |
   | Lowest flock threshold | Rules | fen | `fen.thresholdMin` | 0, 5, 20 | 0.2 |
   | Highest flock threshold | Rules | fen | `fen.thresholdSpan` = max(0, high − low) | 0, 5, 20 | 0.8 |
   | Sky likes an against reply | Rules | hollow | `hollow.drama.against` | 0, 100, 3 | 3 |
   | Sky likes a keep | Rules | hollow | `hollow.drama.keep` | 0, 100, 3 | 2 |
   | Sky likes an away reply | Rules | hollow | `hollow.drama.away` | 0, 100, 3 | 1 |
   | Gift warmth | Rules | halcyon | `halcyon.giftWarmthMultiplier` | 0, 10, 10 | 0.2 |

   The Fen, Hollow, and Halcyon knobs are spec 13.1's "flock thresholds" and "sky rules", and Halcyon's free gifts. "Landscapes", "voting rules", and "song preferences" come with their valleys in M5.
3. **The four advanced switches (spec 13.1).** Each is a scenario field the sim reads only when present, so the M0 golden hash does not move.

   | Switch (label) | Default | Off or on means |
   | --- | --- | --- |
   | One-way ties | on | On is ADR 0002 item 2 (a friend is one side's warmth above `friend.threshold`). Off sets scenario `network.mutual`: `friendsOf` counts a friend only when both sides are above it, for gossip, the dance, imitation, the mushroom, and leaving alike. |
   | Weighted ties | off | On sets `network.weighted`: complex contagion compares the listener's summed warmth toward the friends who hold the opinion with its summed warmth toward all its friends, against its Ear. No draw. |
   | Mixed thresholds | on | On keeps each creature's own Ear. Off gives every creature the Gossip threshold knob's Ear. |
   | Rumors that change as they travel | off | On sets `network.drift`: an adopted opinion's value is the holders' mean plus a uniform draw from −`gossip.drift` (0.2) to +`gossip.drift`, clamped to [−1, 1]; one draw per adoption, after the gossip's other draws for that listener, in adoption order. A retold rumor can flip its sign. |

4. **The seasons turn in the sandbox.** With scenario `seasonDays` n, at the dusk that ends day d, when (d + 1) is a multiple of n, the season becomes the next one in `SEASONS` order (thaw goes to spring). No draw. The snapshot carries the season and the day. In Kith the palette follows the season; a valley keeps its own palette (spec 7.3).
5. **Sandbox verbs (spec 8).** The sim accepts these only in a world with `sandbox`, so a story world ignores them.
   - **Rain** (`{ t: 'rain', x, y }`): every bush within `rain.radius` (120) gains `rain.berries` (2), up to `bush.limit`. No draw.
   - **Welcome** (`{ t: 'welcome', on }`): with the gate dark, no newcomer arrives; it is lit at the start. The Population panel shows it as a switch, "Light the gate for newcomers".
   - **Draw paths** (`{ t: 'path', x, y, x2, y2 }`): a path structure between two points, clamped to the scene; a path shorter than `meet.radius` is ignored. When a creature picks a goal while it stands within `path.reach` (40) of a path end (the nearest such end; a tie goes to the earlier structure), one draw: below `goal.pathChance` (0.5) it walks to that path's other end. A creature near no path end takes no draw, so a world without paths draws as before.
   - **Place**: bench, berry bush, bridge, or lantern, picked in the Population panel, with no limit but the Bell challenge's two bridges (item 6).
   - **Pin a note** (spec 8): a note of at most 80 characters on one tick of the timeline. Notes stay on the device: they are kept with the sandbox save and never go in a link or an export. A rule change drops them, since they mark moments of the old run.
   - Shine, fog, wind, threads, and whisper are the Part 1 verbs. The tools sit in their panels: Population (place, paths, the gate), Weather (shine, fog, wind, rain), Network (threads, whisper). The three-tool limit (spec 11.3, 12.2, ADR 0012 item 8) belongs to the story screen; in the sandbox, keys 1 to 8 pick the eight tools in panel order.
6. **The three challenges (spec 13.1).** A challenge starts from a new valley of the current seed, with the player's knobs and switches, plus its own start. Its card shows the spec's text, which is the user's (ADR 0010), and a pass or fail line (`[PLACEHOLDER]` until a writer delivers). A finished challenge offers "Try again". Nothing is scored or kept, so there is no streak and no ranking (spec 3.4).

   | Id | Text (spec 13.1) | Start | Passed | Failed |
   | --- | --- | --- | --- | --- |
   | winter | "Get through winter with nobody leaving." | autumn | the season turns from winter to thaw with no `leave` event while it was winter | a `leave` event while it is winter |
   | bell | "Make Bell dance with only two bridges." | thaw; chapter 9's brook (one water strip at x 780, 60 wide, the scene's height); Bell's dance threshold 3 (ADR 0012 item 6); at most 2 bridges | a `dance` event for Bell | the season turns from thaw to spring first |
   | krit | "Soften Krit's spikes by spring." | winter; Krit's shell tightness 0.3, bristle 0.6, color 0, softness 0 (its resting shell too, as after a hungry winter) | the season turns to spring with Krit's softness at least `softAt` | the season turns to spring below it |

   In the Bell challenge the card has a "Start the dance" button, once per run: it sends `{ t: 'dance', who: 'pim' }` as a player command, so it is in the link's script, as chapter 9's beat does (ADR 0012 item 6). `softAt` starts at 0.3. Calibration: over seeds 1 to 20, a scripted player passes each challenge in at least 16 and an idle player in at most 4. Calibration changes only a challenge's start fields, `softAt`, and the scripted player; never a check. Each try goes below with its numbers.
7. **Seed links (spec 15.2).** A link is `<page URL>#v1.<data>`.
   - `<data>` is the URL-safe base64 (no padding) of the browser's own `CompressionStream('deflate-raw')` output over the UTF-8 JSON of `{ v: 1, tuning, setup, script, tick }`: the 8-hex tuning hash (`hashTuning` of the raw tuning JSON), the sandbox setup (seed, valley, Kith carry or null, challenge, knobs, switches, structures), every accepted command list with its tick, and the tick the link was made at.
   - **Privacy.** A link holds ids, numbers, and fixed words only. Its schema is strict: every object has only its listed fields, every id field (creature, structure, valley, challenge) matches `^[a-z0-9-]{1,40}$`, and every other string field is a fixed enum. Encoding throws and decoding refuses anything else. The sandbox has no hero, and a carry in a link has no diaries, so a hero's name, a caption, a note, or a diary line has no field to ride in.
   - **Size.** When the whole URL would be longer than 2,000 characters, the Share panel offers a small file instead: `fair-weather-valley.fairweather`, which holds the same `v1.<data>` text on one line. "Open a valley file" reads it. A link holds at most 100 days (40,000 ticks at the sandbox's 400 ticks a day) and 10,000 command lists, and its JSON at most 1 MiB; past 100 days the Share panel says "A link can hold at most 100 days. Start the valley again to share it."
   - **Opening.** A link opens the sandbox for anyone, also before Part 1 ends (the link is the sender's valley); the title's Sandbox button stays locked. The worker replays the script in one scripted fast-forward to the link's tick, and the valley waits there, paused. The fragment then leaves the address bar (`history.replaceState`), so a reload does not replay it again. An opened link replaces the player's own sandbox save only once the player acts in it (a command or a rule change).
   - **Old or broken.** A link whose version is not `v1`, whose tuning hash is not this build's, or whose data does not decode, inflate, parse, or pass the schema, opens the spec 12.8 page: "This valley could not be found", with a "Start fresh" button that goes to the title. A changed tuning would grow a different valley, so a link from an older build counts as old.
8. **Exports (spec 13.4, 15.3).** The game makes every export on the device and saves it as a download. It sends nothing. Each export button carries the line "The image shows the words that you wrote. It stays on this device until you share it."
   - **Pages as PNG.** A journal spread and a *Book of Skies* page draw from the same data as their HTML (the journal entry, the book page) into a 2D canvas 1080 pixels wide, with 72-pixel margins, on the normal paper (`#f6f1e7`) in ink (`#1f2a33`) whatever the contrast setting, in Atkinson Hyperlegible (item 14): the title 48 px bold, a heading 32 px bold, text 28 px, a note 24 px italic, each line 1.4 times its size. Text wraps at spaces; a word wider than the line breaks between characters (whole graphemes). The PNG has no metadata. Files: `fair-weather-journal-<valley>.png` and `fair-weather-year-<n>.png`. The image is a file, not the interface; on screen the text stays HTML (spec 17).
   - **The postcard GIF.** Only in the sandbox, a ring keeps the frames of the last 5 seconds, at most 12 a second (the boil rate, spec 11.2), so at most 60, each 480 pixels wide and 480 × the scene's aspect high (270 for a 1600 × 900 scene). The export adds a 48-pixel paper band under the scene with the caption (at most 60 characters) in 20-px ink, so the GIF is 480 × 318. The encoder builds one 256-color palette by popularity over 15-bit colors of every frame, maps each pixel to its nearest palette color, and writes GIF89a with LZW (minimum code size 8), a NETSCAPE2.0 block that loops forever, each frame's delay from its capture times in hundredths of a second (at least 2), and no comment block. File: `fair-weather-postcard.gif`. The canvas holds no HTML, so no name from the screen is in the frames; the caption is the player's own, added at the moment of export.
9. **Analytics (spec 15.4).** The spec says the game sends counts but has no server (spec 3.4, 21.3), so the client half ships and the endpoint is the user's to choose. A build offers the Settings switch only when `VITE_ANALYTICS_URL` is set at build time; with none, the game has no path to send anything. The switch is off by default and reads "Send counts to help us make the game better", with the line "When this is on, the game sends only three counts: the chapters that you get to, the bets that you get right, and the minutes in the sandbox. It sends no names, no words that you write, and nothing that can identify you or this device." Each count is one independent request with no id, no time, and no order, so the receiver can only add them up:
   - `{ "v": 1, "e": "chapter", "chapter": "<id>" }` when a chapter starts;
   - `{ "v": 1, "e": "bet", "chapter": "<id>", "right": <bool> }` for each bet when its chapter ends;
   - `{ "v": 1, "e": "sandbox", "minutes": <n> }` when the player leaves the sandbox after at least one whole minute with the tab visible (whole minutes, rounded down).

   Each is `fetch(url, { method: 'POST', body, keepalive: true, credentials: 'omit', referrerPolicy: 'no-referrer', cache: 'no-store' })` with the body as `text/plain`, so no cookie and no referrer go with it. A failed send is dropped: nothing is queued or stored. The analytics code is in `src/persist`, the module that turns state into things that leave the game (files, URLs, counts). A request still shows the receiver the device's network address; the payload holds none, and the endpoint's operator must not keep it (open for the user).
10. **No WebGL: the still version (spec 12.8).** At load the game asks for a `webgl2` or `webgl` context on a scratch canvas. With neither, Begin and Continue open the still version: one page per chapter in play order, with the chapter's title, its still image, every line of the Ink knots its beats play, in beat order (the beats triggered by `{ closeCall: true }` left out, and no variant), read with the default flags, and its margin notes as HTML. "Back" and "Next" move between pages, and after the homecoming the page reads "The End" with "Back to title". Continue opens the page of the autosave's chapter and changes no save. The still image is the chapter's `still` (an optional config field) or its scene's placeholder, `content/placeholder/PLACEHOLDER-still-<scene>.svg`, one for each of the four scenes, until an artist draws one per chapter (ADR 0010). The page says "This browser cannot show the moving valley. You see a still picture of each chapter with all of its text."
11. **Asset retry (spec 12.8, 16).** The game's data is bundled, so the assets that can fail after the page loads are the sim worker's script and the images (journal drawings and stills). Each gets three tries in all: after a failure it waits 1 s, then 2 s (`ASSET_WAITS_MS`, one constant in `main.ts`). A worker that fails before it posts its first message is a failed load; after the third the host gives up, and the game screen shows the still page of the chapter now playing. A crash after the first message keeps ADR 0009's restart and replay. An image that fails three times shows its scene's still image, and if that fails too, its alt text. A WebGL context that fails to start gives the still version at once, with no retry.
12. **Offline after the first load (spec 3.6).** A small hand-written service worker, emitted by a Vite plugin at build time, precaches every file the build writes (the page, scripts, the worker, styles, fonts, images) under a cache named by a hash of that list. It answers every same-origin GET from the cache first and the network second, answers navigations with the cached page, and deletes older caches when it activates. A new version waits for the next load (no `skipWaiting`), so one page never mixes chunks of two builds. It never caches another origin, so analytics never touch it. Only a production build registers it (`import.meta.env.PROD`, which `vite build --mode development` also sets); the dev server never does.
13. **"Where this model is wrong" (spec 19.1, 20).** A plain page of HTML text from `content/notes/model-limits.json`. Its first items are the four limits that spec 19.1 lists, in the spec's own words (the user's text); the writer's further items of what the model leaves out carry `[PLACEHOLDER]` until delivered. The title, the sandbox's Rules panel, and the drawer under the margin notes each have a "Where this model is wrong" button that opens it.
14. **Type (spec 12.7).** Body text is Atkinson Hyperlegible, from `@fontsource/atkinson-hyperlegible` (weights 400 and 700, OFL-1.1), bundled with the build so it works offline; the text-size setting stays. Until the designer delivers the hand-lettered display face, titles use Atkinson Hyperlegible bold. That face is art (ADR 0010): a placeholder until then, though no build guard can see it.
15. **The phone layout (spec 12.4).** In portrait (the viewport taller than it is wide), the scene ends above the bottom bar (status, tools, ribbon), so no tool covers the scene. Below 600 CSS pixels of width, the drawer, the journal, the *Book of Skies*, the sandbox panels, and the share and export dialogs become full-screen sheets. Thread snapping and pinch zoom are M2's.
16. **Performance (spec 11.4, 17, T9).** CI checks the draw-call budget only: the heaviest Meadow frame (30 creatures, fog, the lens, the brook with two bridges, a lantern, the mushroom, the heat map, and two paths) takes at most 100 draw calls. Frame time is the user's measurement on real devices, since CI has no GPU: on the reference desktop, mean at most 16.9 ms and p95 at most 20 ms (the M0 budget, 60 fps); on the reference phone, mean at most 33.4 ms and p95 at most 40 ms (30 fps), with 30 creatures in the Meadow. Spec 22 leaves the reference phone open, so the user names it. A Chromium run with 4× CPU throttling at a 412 × 915 viewport is printed as a proxy and never asserted.
17. **The launch tests.**
    - **T7, "all runs reach their end screen".** The auto-player and the keyboard-only runs play Part 1 and Part 2 to "The End" (M2, M3). The phone run (Pixel 7, touch only) and the reduced-motion run go from Begin to "The End" by pressing each chapter's Skip once its first snapshot has come, and check the layout and the stopped boil on the way; the no-WebGL run pages the still version to "The End". So none of them waits on how fast CI draws or steps.
    - **T8.** New baselines (the sandbox Meadow with paths and a dark gate) are approved by the user before they are committed; earlier baselines must not change. Visual stays a manual gate (CI's Chromium is not the baselines' build).
    - **T10.** axe-core finds no serious or critical issue on every screen and dialog. The screen-reader pass is the user's, with `docs/playtest/screen-reader.md`.
    - **T11.** The five-person playtest against S1 to S4 is the user's, with `docs/playtest/m4.md`.
18. **A new year, a new seed (spec 12.1).** Begin draws a new seed with `crypto.getRandomValues` (one uint32). A development build uses seed 1 unless the address has `?seed=N`, so e2e runs stay fixed. The year keeps its seed: the autosave, Continue, Kith's silent run, and the *Book of Skies* page read it. "A new valley" in the sandbox draws its own.
19. **Dependencies (ADR 0008 items 6 and 7).** Looked up on the npm registry on 2026-11-14.
    - **Seed links use the browser's `CompressionStream`,** not fflate 0.8.3 (latest, 2026-05-16), which this item replaces in ADR 0008 item 6. `deflate-raw` is in every target engine (Chromium 103, Firefox 113, Safari 16.4) and in Node 22, where the unit tests run.
    - **The GIF encoder is our own** (item 8), about a hundred lines, not gifenc 1.0.3 (latest, 2021-03-07, unchanged since): a fixed popularity palette suits flat ink art, and the browser's own `ImageDecoder` checks the output in e2e.
    - **The service worker is our own** (item 12), not vite-plugin-pwa 2.0.0 (2026-10-03) with workbox-build 7.4.1: the precache list and cache-first answers are a few dozen lines.
    - **One new runtime package:** `@fontsource/atkinson-hyperlegible` 5.3.0 (2026-07-19, OFL-1.1), font files only. Pin it exactly, per ADR 0008 item 1.

## Consequences

- Every new sim rule is on only with its scenario field (`sandbox`, `seasonDays`, `baseFog`, `network`), so the M0 golden hash `c29d2fa4dbda4dcf` does not change, and a story world cannot be driven by a sandbox command.
- A seed link replays exactly, because a run's whole start is in its setup and every value in the setup is exact.
- Links break when the tuning changes. That is the cost of a valley that grows the same for sender and receiver.
- Nothing the player writes leaves the device unless the player saves an export and shares the file.
