# M1 playtest kit: the vertical slice

This kit is for the first playtest. The playtest checks success criteria S3 and S4 (spec 3.5).

- **S3:** Each tester explains at least three core ideas without help.
- **S4:** Each tester names at least four different feelings.

Do five sessions. Do one session with one tester at a time.

## 1. Before the session

1. Use a desktop or laptop computer with a keyboard and a mouse.
2. Install the project. Run `npm ci`.
3. Start the game. Run `npm run dev`.
4. Open the address that Vite shows. Do not add `?chapter` or `?fast` to the address.
5. Open the browser tools. Delete the site data for the address. The game then starts with no save.
6. Close the browser tools.
7. In Settings, select Sound.
8. Set the computer volume to a comfortable level.
9. Go back to the title screen.
10. Print one copy of the results table (section 5). Write the tester code on it, for example T1.
11. Have a timer ready.

The development build shows `[PLACEHOLDER]` on some text. This is correct for M1. Tell the tester about it before they play.

## 2. Consent

Read this text to the tester. Use these words.

> Thank you for helping us. You will play a short part of a game for about 20 minutes. Then I will ask you two questions.
>
> We test the game. We do not test you. There are no wrong answers.
>
> We do not record your name, your face, or your voice. We do not record the screen. I write notes on paper. The notes use a code, for example T1, and not your name.
>
> You can stop at any time. You do not have to give a reason. If you stop, I destroy your notes if you ask me to.
>
> Do you agree to play and answer the questions?

Continue only if the tester says yes. If the tester says no, thank them and end the session.

Do not write the tester's name, age, email address, or other personal data on any page.

## 3. During play

Time plan:

| Part | Time |
| --- | --- |
| Setup and consent | 5 minutes |
| Play, chapters 0 to 3 | 15 to 25 minutes |
| Questions | 10 minutes |
| Total | 30 to 40 minutes |

Do these steps:

1. Tell the tester: "Play until the game says that the slice is done. Think out loud if you want to."
2. Start the timer when the tester clicks Begin.
3. Do not explain the game. Do not answer questions about the game during play.
4. If the tester asks for help, say: "What do you think you can do?"
5. If the tester cannot move on for three minutes, tell them about the Skip chapter button. Write it in the notes.
6. Write what the tester says, as near to their words as possible.
7. Write the chapter number next to each note.
8. Write down when the tester laughs, sighs, leans in, or looks away.
9. Stop the timer at the end screen ("End of the first spring"). Write the time.

## 4. Questions

Ask the questions in this order. Ask each question one time. Do not suggest answers.

### Question 1 (S3)

Ask: **"Explain what happened in your own words."**

If the tester stops, ask: "Is there more?" Ask this one time only.

Write the answer. After the session, mark each core idea that the tester explains without help:

| Core idea | Chapters | An example of a pass |
| --- | --- | --- |
| Attention starts trust | 0, 1 | "When I looked at Pim and answered, Pim trusted the sky more." |
| How the sky answers changes the creature | 1 | "If I rumble, they stop waving at me." |
| A creature that always shares can be used by one that keeps | 2 | "Pim gave and gave, and Krit took the berries." |
| Repeated meetings make cooperation pay | 3 | "The bench made the same friends meet again, so they were kind." |
| The game is a model with limits | Notes | "It is a simple model. Real trust is more complex." |

S3 passes for the tester when the tester explains three or more ideas.

### Question 2 (S4)

Ask: **"Name the feelings you had."**

If the tester stops, ask: "Did you have other feelings?" Ask this one time only.

Write each feeling with the tester's word. Do not change the word. If the tester gives the chapter, write it too. If not, ask: "When did you feel that?"

Count different feelings only. "Happy" and "glad" count as one feeling.

S4 passes for the tester when the tester names four or more different feelings.

The planned feeling for each chapter is in the `feeling` field of `content/chapters/ch0.json` to `ch3.json`:

| Chapter | Planned feeling |
| --- | --- |
| 0 | Wonder |
| 1 | Tenderness |
| 2 | Surprise, unease |
| 3 | Relief, warmth |

## 6. After the sessions

1. Count the testers who pass S3. The target is five of five.
2. Count the testers who pass S4. The target is five of five.
3. For each chapter, compare the feelings named with the planned feeling. Write the differences.
4. Write the problems that more than one tester had.
5. Put the results in `docs/playtest/m1-results.md`. Use tester codes only.
6. Destroy the paper notes after you copy them.
